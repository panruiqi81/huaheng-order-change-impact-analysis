## 任务 2 运维手册与责任分工 · 已完成

**日常运行**（沈悦或其指定人员）：

```bash
cd prototype
python3 -m oc_checker --snapshot <本周快照目录> --order <订单号> --out <输出目录>
```

每次运行后核对：`report.md` 首行的任务编号、`manifest.json` 中的输入文件哈希与快照一致。输出目录与 `manifest.json` 一并归档。

**故障处理**：

| 现象 | 含义 | 处理 | 依据 |
|---|---|---|---|
| 结论为“转人工”，有输入问题明细 | 快照缺文件或字段非法 | 不重试、不补数据；把明细发给沈悦修快照；当次核对由人工完成 | f32 |
| 结论为“转人工”，有“需人工确认” | 数据本身有缺项（无质量记录、无库存行等） | 由对应岗位确认后人工补全判断，工具结论不直接使用 | f32、f44 |
| 结论为“硬约束中止” | 订单占用批次冻结 / 返工未检 / 放行无签发人 | 停止对该订单的一切自动化建议；交许文静处理 | f40、f42、f43 |
| 程序报错退出 | 代码或环境问题 | 当次转人工；记录错误信息；修复后规则版本号递增并重跑评估 | f31 |

**铁律**：任何情况下不得用上一次的报告、缓存结果或“估计值”充当本次核对结论（f32）。

**责任分工**：

| 事项 | 责任人 | 升级对象 |
|---|---|---|
| 快照导出与字段口径 | 沈悦 | 周明远 |
| 版本冲突的裁定 | 王建国 + 陈思雨（会签双方） | 周明远 |
| 加班审批 | 工厂经理 + 人事 | 周明远 |
| 质量放行与冻结解除 | 许文静 | —（不可被替代，f01） |
| 缺口处置与对外答复 | 陈思雨（答复后回填） | 周明远 |
| 客服对外口径 | 李佳宁 | 陈思雨 |
| 工具规则变更 | 沈悦 | 许文静（涉及质量规则时） |
| 继续 / 停止 | 周明远 | — |

**责任转移时点**：以会签完成、批准版本明确为准，不以口头通知或系统中先出现的版本为准（王建国在访谈中的待验证假设，需会签双方书面确认后生效）。

## 任务 3 培训与交接验收 · 已完成

**培训对象与内容**：

| 对象 | 需要学会的 | 时长 |
|---|---|---|
| 王建国、生产计划员 | 读报告：已确认 / 待审批的区别；冲突与硬约束中止分别意味着什么；不能拿报告当调整排产的依据 | 60 分钟 |
| 李佳宁、客服 | 用待确认清单答复客户；哪些话能说（已确认）、哪些只能说“正在确认”（待审批） | 45 分钟 |
| 陈思雨、销售 | 会签状态与签发人的确认；缺口处置的答复与回填 | 30 分钟 |
| 许文静 | 暂停条件与暂停权；质量相关发现的复核方法 | 30 分钟 |
| 沈悦团队 | 运行、审计清单核对、故障处理 | 60 分钟 |

**培训中必须讲清的三件事**：

1. 工具只做三件事——核对版本、测算缺口、检查冻结；会签、加班审批、质量放行永远由人做。
2. 报告不是承诺。“预计”与“承诺”的区别由销售把握（f11、f52）。
3. 看到“硬约束中止”或“转人工”时，正确动作是停下来找人，不是想办法让工具给出结论。

**交接验收标准**（全部满足才算交接完成）：

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 业务方能独立完成一次运行并解释报告每一节 | 王建国现场演示 |
| 2 | 业务方能凭任务编号从报告回溯到输入快照 | 李佳宁或其指定人员演示 |
| 3 | 各岗位能说出自己负责的待确认项与升级对象 | 口头抽查 |
| 4 | 三方评审签字齐全 | 放行门禁表 |
| 5 | 运行手册、评估结果、试点记录已归档到仓库 `docs/` | 仓库目录 |

**交付下一阶段**：签字齐全的放行门禁表、归档的手册与记录，作为运营迭代的起点。
