# FDE 训练 · 阶段 09 运营迭代（华衡智造案例）

> 阶段目标：上线之后怎么知道它还在正常工作、怎么改、什么时候该扩。
> 责任人：周明远（业务结果）、沈悦（运行与版本）｜质量规则变更须许文静评审
> 输入：阶段 08 的放行门禁表与归档记录
> **说明**：案例为合成业务现场。本阶段完成的是监控指标、反馈闭环、版本管理与扩展评估的机制设计；机制的实际运行数据须在上线后产生。

## 任务 1 运营监控与指标看板 · 已完成

**两类指标**：

| 类别 | 指标 | 口径 | 看的人 | 频率 |
|---|---|---|---|---|
| 业务结果 | 排产版本一致率 | 排产版本 = 已批准版本的订单数 ÷ 当期排产订单数（王建国确认后计数） | 周明远、王建国 | 周 |
| 业务结果 | 追问轮次 | 同一订单号归集的追问次数 | 李佳宁 | 周 |
| 业务结果 | 准时交付率 | 试点前书面确认的口径，全程沿用（f02） | 周明远 | 月 |
| 业务结果 | 变更响应 B 段 | 录入 ERP → 可对外答复，起止口径确认后固定 | 陈思雨 | 周 |
| 工具健康 | 结论分布 | 一致 / 需关注 / 冲突 / 硬约束中止 / 转人工 各占比 | 沈悦 | 周 |
| 工具健康 | 转人工率 | 转人工次数 ÷ 运行次数 | 沈悦 | 周 |
| 工具健康 | 修正率 | 工具结论经人工复核后被修正的次数 ÷ 总次数 | 许文静 | 周 |
| 工具健康 | 待确认项答复率 | 在约定时限内得到答复的待确认项 ÷ 全部待确认项 | 李佳宁 | 周 |
| 审计 | 可回溯率 | 能凭任务编号回溯到输入快照与规则版本的报告 ÷ 全部报告 | 沈悦 | 月 |

**预警阈值**（超过即触发复盘，由沈悦召集）：

| 指标 | 阈值 | 含义 |
|---|---|---|
| 修正率 | > 10% | 规则与业务判断出现系统性偏差 |
| 转人工率 | > 30% | 快照质量或字段口径有问题 |
| 可回溯率 | < 100% | 审计断链，当期结果视为无效（f31） |
| 待确认项答复率 | < 80% | 问题在流程而不在工具，升级到周明远（f54） |
| 质量相关错误放行 | ≥ 1 次 | 立即暂停（f43） |

**原则**：指标只用于同一口径下的前后对比；口径变更须由周明远书面确认，并从确认之日重新起算（f02、f04）。

## 任务 2 反馈闭环与版本迭代 · 已完成

**反馈来源**：

| 来源 | 记录内容 | 汇总到 |
|---|---|---|
| 王建国复核 | 工具结论与人工判断不一致的地方，附订单号与任务编号 | 沈悦 |
| 李佳宁答复 | 哪条待确认项找不到答复人、哪条表述容易被误读成承诺 | 沈悦、陈思雨 |
| 许文静复核 | 质量相关发现是否有遗漏或误报 | 沈悦 |
| 运行记录 | 转人工原因、输入问题明细 | 沈悦 |

**处理流程**：

```
反馈登记 → 分类（数据问题 / 规则问题 / 表述问题 / 流程问题）
  → 数据问题：沈悦修快照口径
  → 规则问题：改规则 → 版本号递增 → 评估集补用例 → 全部通过 → 许文静评审（涉及质量规则）→ 发布
  → 表述问题：改报告模板 → 走读确认
  → 流程问题：不在工具里解决，升级到对应责任人
```

**版本管理规则**：

1. 规则版本号 `rules-huaheng-x.y.z`：改判定逻辑升 x，加规则升 y，改文案升 z。
2. 每次变更必须在 `eval/cases.py` 里有对应用例，先写预期再运行；17 个既有用例不得回退。
3. 任务编号包含规则版本，旧报告可按版本号区分是由哪一版规则生成的（f31）。
4. 变更记录写入仓库，与报告一同归档。

**待验证的迭代候选**（按价值与风险排序，均未排期）：

| 候选 | 价值 | 风险 | 前置条件 |
|---|---|---|---|
| 一单多排产（跨产线）的缺口合并 | 中 | 低 | 取得跨产线订单样本 |
| 用自然语言解释每条发现的依据 | 中：一线更易读 | 中：可能过度断言 | 需另建评估集，逐条核对不超出已有记录（f45） |
| 主动提示“某待确认项已超时未答复” | 中：减少搁置 | 低 | 约定时限由业务方确定 |
| 从提醒扩展到变更看板（阶段 04 的 C 方案） | 中 | 低 | 一线确认需要 |
| 与 ERP / MES 的定时对接 | 高：免去手工导出 | 中：涉及接口权限 | 沈悦批准只读接口，仍不写入（f30、f35） |

**明确不做**：自动调整排产、自动对客户发送、自动解除冻结、以返工完成等同检验通过（f13、f30、f42）。

## 任务 3 规模化评估与二期路线 · 已完成

**规模化前必须回答的问题**：

| 问题 | 为什么要先答 | 由谁答 |
|---|---|---|
| 实测的 N、M、L 是否支持 ROI | 阶段 04 的测算显示纯工时口径多数情景不回本 | 周明远、王建国、陈思雨 |
| “已批准版本”定义是否已稳定运行一个周期以上 | 定义变了，历史数据不可比 | 王建国、陈思雨 |
| 一线是否真的在用 | 没人用的工具扩产线只是放大维护成本 | 王建国、李佳宁 |
| 其他产线的会签规则、质量规则是否相同 | 不同则规则需分支，版本管理复杂度上升 | 王建国、许文静 |

**扩展路径**（逐级，每级通过后才进下一级）：

| 级别 | 范围 | 进入条件 |
|---|---|---|
| 1 | L1 产线稳定运行 | 阶段 08 交接完成，连续 4 周修正率 ≤ 10% |
| 2 | 同类产线（会签与质量规则相同） | 级别 1 达标 + 实测 ROI 在至少一种口径下成立 |
| 3 | 跨产线、一单多排产 | 级别 2 达标 + 规则差异梳理完成 |
| 4 | 定时只读对接 | 沈悦批准只读接口；审计清单自动化归档 |

**停止扩展的条件**：任一产线出现质量相关错误放行；准时交付在统一口径下下降；修正率连续两周超过阈值。

**二期的另一个方向**：阶段 02 的四来源收敛指出 Brief（书面范围）与 Industry（行业依据）缺证。规模化之前应补上这两项——书面 Brief 明确范围与排除，行业依据说明同类制造企业在变更协同上的做法——否则二期需求仍只能建立在角色陈述上。

**交付**：监控指标、反馈闭环、版本规则与扩展路径，作为上线后的运营依据。
